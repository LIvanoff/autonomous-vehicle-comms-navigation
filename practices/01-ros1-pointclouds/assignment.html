Верните облаку правильную ориентацию

Вам выдан короткий ROS 1 bag с реальными данными верхнего лидара Ouster. Во все облака внесён один и тот же неизвестный поворот. Напишите ноду, которая получает облако из топика, поворачивает координаты точек и публикует исправленное облако.

Что значит «правильно»: дорога находится внизу и примерно горизонтальна, вертикальные объекты направлены вверх. Начало координат остаётся в лидаре, поэтому дорога не обязана находиться на Z=0. Перенос, масштабирование, отражение и удаление точек не нужны. Направление вокруг вертикали (yaw) без внешнего ориентира не оценивается.

1. Что дано и что делаете вы

Готово в заготовкеНужно написать
Docker с ROS 1 Noetic, Python 3, NumPy. Разбор двоичного PointCloud2; запись результата; изображения без X11.Матрица поворота; применение к точкам; ROS Publisher и Subscriber; callback. Затем подобрать углы по изображениям.

В student_node.py четыре TODO. Для первой проверки можно временно вернуть единичную матрицу и копию массива: результат должен совпасть с входом. После этого добавляйте поворот.

input.bag → rosbag play → /points_raw → ваша нода → /points_corrected → corrected.bag → PNG/GIF

Нода подписывается на поток сообщений. Сам файл читает готовый rosbag play. Это позволяет потом заменить запись настоящим драйвером лидара без переделки вашей ноды.

2. Запуск без RViz и X11

До пары установите Docker Desktop с Linux containers и соберите образ. Распакуйте общую заготовку, а свой input.bag положите рядом с compose.yaml. Все команды запускаются из этой папки; одинаково в PowerShell и Linux shell.

docker compose build
docker compose run --rm lab bash -lc "source /opt/ros/noetic/setup.bash && rosbag info input.bag"
docker compose run --rm lab bash -lc "source /opt/ros/noetic/setup.bash && python3 preview.py input.bag --out output/before"

Откройте output/before/index.html обычным браузером на своём компьютере. В папке также будут PNG и animation.gif. Доступ к графическому экрану контейнеру не нужен.

После реализации TODO и изменения config.yaml:

docker compose run --rm lab bash -lc "source /opt/ros/noetic/setup.bash && python3 -m unittest test_student -v"
docker compose run --rm lab bash -lc "source /opt/ros/noetic/setup.bash && python3 run_lab.py input.bag --out output/attempt01"

Команда поднимет отдельный ROS master, вашу ноду и запись выходного топика. Бэг проигрывается на половинной скорости, затем строятся картинки. Откройте output/attempt01/preview/index.html. Для следующей попытки используйте attempt02: предыдущие результаты сохраняются.

Для быстрого подбора можно отключить отрисовку всех кадров и нарисовать один:

docker compose run --rm lab bash -lc "source /opt/ros/noetic/setup.bash && python3 run_lab.py input.bag --out output/attempt02 --no-preview"
docker compose run --rm lab bash -lc "source /opt/ros/noetic/setup.bash && python3 preview.py output/attempt02/corrected.bag --topic /points_corrected --out output/attempt02/preview --step 20"

3. Как подбирать углы

  1. Сначала посмотрите XZ и YZ: сверху наклон дороги виден хуже. Оси и камера между попытками не меняются.
  2. Если дорога оказалась над датчиком, попробуйте грубый разворот на 180° вокруг горизонтальной оси. Не меняйте знак только одной координаты: это отражение, а не поворот.
  3. Подбирайте roll и pitch сначала шагом 10–15°, затем 2–3°. Проверяйте обе боковые проекции после каждого изменения.
  4. Сравните начало, середину и конец записи. Хорошая ориентация должна сохраняться на всём фрагменте.
  5. Не пытайтесь сделать идеально горизонтальной каждую точку дороги: существуют уклон, бордюры, шум и движение автомобиля. У одного бэга — одна постоянная коррекция.

Для сдачи достаточно восстановить вертикаль с допуском 3° относительно подготовленного эталона. Преподаватель проверит угол отдельно. Этот допуск — учебный критерий, а не спецификация точности лидара или калибровки.

4. Как понимать матрицы

Поворот меняет координаты одной и той же точки. Для точки-столбца p=[x,y,z]ᵀ договоримся:

p_out = R · p_in
R = Rz(yaw) · Ry(pitch) · Rx(roll)

Rx = [[1,  0,   0],   Ry = [[ cp, 0, sp],   Rz = [[cy, -sy, 0],
      [0, cr, -sr],         [  0, 1,  0],         [sy,  cy, 0],
      [0, sr,  cr]]         [-sp, 0, cp]]         [ 0,   0, 1]]

cr = cos(roll), sr = sin(roll); аналогично pitch и yaw.
Перед sin/cos переведите градусы в радианы.

Справа налево: сначала Rx, затем Ry, затем Rz, все вокруг фиксированных осей. В массиве NumPy каждая точка лежит строкой. Подумайте, какая матрица должна стоять справа при обработке сразу N точек. Проверьте на примере: +90° вокруг Z переводит (1,0,0) в (0,1,0).

config.yaml содержит углы вашей коррекции. Это не известные углы испорченного датчика. Для известной матрицы искажения обратная равна транспонированной, но при подборе по виду облака вы сразу ищете исправляющий поворот. Простая смена знаков трёх углов при сохранении порядка в общем случае не даёт обратную матрицу.

5. Контракт сообщений

  • Вход: /points_raw, тип sensor_msgs/PointCloud2, frame lidar_corrupted.
  • Выход: /points_corrected, тот же тип, frame lidar_level.
  • Сохраняйте header.stamp, размер и порядок точек, intensity и остальные поля. Метка времени — момент измерения, а не момент обработки.
  • Обрабатывайте только точки, у которых все x/y/z конечные. Строки с NaN/Inf оставляйте на месте и без изменения.
  • Не используйте create_cloud_xyz32, если из-за него теряются дополнительные поля. Готовый replace_xyz сохраняет структуру и поля сообщения.
  • Изменение только frame_id не вращает координаты. static_transform_publisher вместо обработки и публикации нового облака это задание не выполняет.

run_check.json проверяет число облаков и метки времени. Успешная проверка доставки ещё не означает, что облако ориентировано правильно.

6. Что сдавать

Сдайте student_node.py, config.yaml, номер варианта, corrected.bag, run_check.json, изображения до/после и 5–8 предложений о подборе углов. Покажите две промежуточные попытки. Итоговую запись берите из последней попытки; картинки должны соответствовать ей.

Изображения дополняют работающую ноду и выходной бэг. Отсутствие X11/RViz не мешает сдаче. Автооценка нормали земли через RANSAC — необязательное продолжение после сдачи основного задания, не входит в обязательную часть.

Если RViz уже работает

В готовом Linux-окружении с ROS 1 и RViz запустите roscore, отдельно rosbag play --clock output/attempt01/corrected.bag и rviz -d view_corrected.rviz. Выберите Fixed Frame lidar_level. Для просмотра исходного бэга используйте lidar_corrupted и /points_raw. Отсутствующее преобразование между этими frame нельзя заменять выдуманным identity TF. В базовый Docker GUI намеренно не включён; обязательный сценарий — PNG/GIF.

Если что-то не работает
  • NotImplementedError: заполните TODO; заготовка не содержит решение.
  • Нет выходных сообщений: проверьте student.log, имена топиков и Publisher/Subscriber.
  • Потери облаков: уберите рисование из callback и повторите с --rate 0.25.
  • TF error в RViz: Fixed Frame должен совпадать с frame отображаемого облака.
  • Docker не подключается: запустите Docker Desktop и Linux containers до пары.
  • Дорога исчезла: сравните PNG с прежними осями; не меняйте автоматический масштаб. При необходимости задайте одинаковый --radius для обеих картинок.
