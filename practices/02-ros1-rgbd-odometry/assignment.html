RGB-D-одометрия: как камера измеряет движение

ROS 1 Noetic · OpenCV · Rerun

На этом занятии мы разберём, как по цветному изображению и глубине определить движение камеры. Ваша задача — дополнить ROS-ноду, запустить её на записи TUM RGB-D и сравнить полученную траекторию с эталонной. Выполните один запуск с настройками из config.yaml; изменять параметры алгоритма не требуется.

Математическую часть и синхронизацию сообщений я предоставляю готовыми. От вас требуется подключить алгоритм к ROS и объяснить результат. GPU, X11, Git и отдельная установка Python не нужны. До занятия должны быть установлены Docker Desktop с Linux containers и загружены образы.

1. Подготовить рабочее место

Распакуйте папку в доступное для записи место. Откройте PowerShell или терминал Linux в папке с compose.yaml. Проверка окружения:

docker version
docker compose version
docker image ls

Нужны образы mirea-rgbd-vo:noetic-v1 и mirea-rgbd-viewer:0.23.4. Если их ещё нет, заранее выполните docker compose build либо загрузите полученный от меня архив через docker load -i rgbd-images.tar.

Откройте контейнер ROS:

docker compose run --rm lab bash

Внутри него выполните:

source /opt/ros/noetic/setup.bash
cd /lab/catkin_ws
catkin_make -j2
source devel/setup.bash
cd /lab
rosbag info data/tum_rgbd_12s.bag

catkin_make находит пакет и подготавливает его запуск. У Python-ноды нет компиляции в машинный код. Команда source devel/setup.bash добавляет пакет в окружение текущего терминала.

2. Дописать ноду

Откройте student_node.py обычным редактором на своём компьютере. Папка подключена к контейнеру, поэтому сохранённые изменения сразу доступны внутри ROS.

  1. Создайте rospy.Publisher для топика /vo/pose, тип PoseStamped, очередь 10. Сохраните объект в self.pub.
  2. Создайте три message_filters.Subscriber: self.rgb_sub для /camera/rgb/image_raw (Image), self.depth_sub для /camera/depth/image_raw (Image), self.info_sub для /camera/rgb/camera_info (CameraInfo). Для всех задайте queue_size=10, для двух изображений также buff_size=2**25. Удалите строку raise NotImplementedError(...). Готовый блок TimeSynchronizer оставьте без изменений.
  3. В callback передайте color, depth, info в self.lab.process_messages(...) и сохраните результат.
  4. Если результат не равен None, опубликуйте его через свой publisher.

Callback получает три согласованных сообщения: RGB, depth и параметры камеры. Подписчики создаёте вы. Готовый блок TimeSynchronizer в ноде хранит до 20 сообщений каждого входа и вызывает callback, когда получена тройка с одинаковым header.stamp. Порядок аргументов callback совпадает с порядком подписчиков в списке. process_messages возвращает готовый PoseStamped или None, если кадр пропущен по настройке либо оценка ненадёжна. При None не публикуйте выдуманное или старое положение с новой меткой времени.

3. Собрать и запустить

В контейнере после сохранения файла:

cd /lab/catkin_ws
catkin_make -j2
source devel/setup.bash
cd /lab
python3 run_lab.py data/tum_rgbd_12s.bag --out output/attempt01

Скрипт действительно запускает вашу ноду через rosrun rgbd_vo_lab student_node.py и проигрывает bag. Скорость проигрывания 0,25 выбрана, чтобы обычный ноутбук успевал обрабатывать кадры. Данные и физические временные метки остаются исходными.

После успешного запуска появятся report.json, poses.bag, логи и данные для Rerun. Для следующего опыта указывайте новую папку, например output/attempt02. Старые попытки сохраняются.

4. Посмотреть результат в Rerun

В новом терминале компьютера, в папке практики:

docker compose run --rm --service-ports viewer python viewer/show.py output/attempt01 --serve

Откройте Rerun в браузере. Нужен современный Chrome или Edge с поддержкой графики WebGPU/WebGL. Отдельный сервер X11 не нужен.

  • Траектории: оранжевая — оценка, зелёная — эталон. Первая вкладка — проекция на плоскость XZ первой камеры (ось Y здесь не показана); следующая — полный 3D-путь. Начало координат находится в первой камере.
  • Карта RGB-D: отдельная вкладка с точками сцены. Это разреженный предпросмотр, он может двоиться из-за ошибки движения.
  • Соответствия: зелёные линии поддержали модель, красные отвергнуты. Линия соединяет координаты детали в опорном и текущем кадрах; это не вектор скорости автомобиля.
  • Глубина: измеренное расстояние вдоль оптической оси, в метрах. Нулевые значения означают отсутствие измерения.
  • Проверка: число полученных оценок, потери отслеживания и ошибка относительно эталона.

Если шкала времени скрыта, откройте её кнопкой панели времени в правом верхнем углу Rerun. Перемещайте указатель по кадрам и включите воспроизведение. Для скорости, близкой к исходной записи, выставьте 10 FPS вместо стандартных 30 FPS. Это только скорость просмотра, она не меняет вычисленные позы. После просмотра нажмите Ctrl+C в терминале viewer. Сохранённый recording.rrd остаётся в папке результата.

5. Разобрать результат

Откройте output/attempt01/report.json. Сопоставьте отчёт с траекториями в Rerun: насколько близки оценка и эталон, где видны расхождения и были ли потери отслеживания.

processed — обработано кадров; published — опубликовано поз; lost — число потерянных оценок; tracking_fraction — доля успешных оценок среди обработанных кадров; position_rmse_m — среднеквадратическая ошибка положения в метрах.

RMSE считается только по опубликованным позам. Потерянные оценки в эту метрику не входят, поэтому рассматривайте ошибку и долю успешных оценок вместе.

6. Что сдать

  • Дополненный student_node.py.
  • Файл report.json успешного запуска и снимок Rerun с оценённой и эталонной траекториями.
  • Короткие ответы: откуда взялись метры; зачем нужна глубина; почему возможны потери; что показывает RMSE и почему нужно также учитывать потери отслеживания.

Объясните одну цепочку своими словами: кадры → соответствия → 3D-точки по глубине → PnP → преобразование позы → публикация.

Если что-то не работает

  • Docker не отвечает: запустите Docker Desktop, дождитесь готовности Linux engine.
  • TODO / node exited: проверьте четыре места в student_node.py и output/attempt01/student.log.
  • Пакет не найден: выполните catkin_make и source devel/setup.bash именно в текущем контейнере.
  • Not all RGB-D frames received: повторите запуск медленнее в новой папке: python3 run_lab.py data/tum_rgbd_12s.bag --rate 0.1 --out output/attempt01_slow. Временные метки данных сохраняются.
  • Папка результата уже существует: задайте новый номер попытки.
  • Порт занят: остановите предыдущий viewer через Ctrl+C. В крайнем случае docker compose down остановит контейнеры этой практики.
  • Rerun пустой: дождитесь строки Saved в терминале, затем обновите страницу. Проверьте полный адрес с параметром url=....
  • Браузер не создаёт графический контекст: используйте актуальный Chrome/Edge или откройте файл RRD в нативном Rerun версии 0.23.4.

По завершении выполните exit в ROS-контейнере. Благодаря --rm он удалится автоматически. Файлы в папке практики сохранятся.

Источники и границы результата

TUM RGB-D, последовательность freiburg1_xyz. Формат глубины и рекомендуемые параметры. OpenCV PnP. Rerun.

Это учебная одометрия между кадрами, без bundle adjustment и замыкания петли. Эталон совмещается с первой позой, масштаб и вся траектория под результат не подгоняются. Глубина TUM совмещена с RGB; в учебном бэге ближайшая depth-пара в пределах 20 мс получает метку RGB для точной ROS-синхронизации. Исходные метки сохранены в manifest. nuPlan с одной RGB-камерой не подходит для запуска этой RGB-D-ноды.
