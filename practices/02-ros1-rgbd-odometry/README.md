# Практика 2. RGB-D-одометрия в ROS 1

**ROS 1 Noetic · OpenCV · Rerun**

На этом занятии мы разберём, как по цветному изображению и глубине определить движение камеры. Ваша задача — дополнить ROS-ноду, запустить её на записи TUM RGB-D и сравнить полученную траекторию с эталонной.

Математическую часть и синхронизацию сообщений я предоставляю готовыми. От вас требуется реализовать взаимодействие ноды с ROS, получить результат и объяснить его. Выполните один запуск с настройками из `config.yaml`; изменять параметры алгоритма в этой работе не нужно.

## До занятия

- Установите и запустите Docker Desktop с Linux containers (либо Docker Engine с Compose на Linux).
- Распакуйте архив практики целиком в папку, доступную для записи.
- [Скачайте учебный бэг TUM отдельно](https://github.com/LIvanoff/autonomous-vehicle-comms-navigation/raw/29c96ba7e98efba7c77fafe587646913174e33c1/practices/02-ros1-rgbd-odometry/data/tum_rgbd_12s.bag) (около 75 МБ) и сохраните его как `data/tum_rgbd_12s.bag`. Без этого файла запуск невозможен.
- Подготовьте Docker-образы по инструкции ниже.
- Подготовьте редактор кода и браузер Chrome или Edge с работающим графическим ускорением.

Образы занимают около 4,8 ГБ суммарно по данным Docker; для сборки, кэша и результатов предусмотрите дополнительное свободное место.

GPU, X11, Git и Python на компьютере не требуются: необходимые программы запускаются в контейнерах. Проверка выполнена на Windows с Docker Linux amd64; другие архитектуры отдельно не проверялись.

Откройте PowerShell или терминал Linux **в папке практики, где лежит `compose.yaml`**:

```sh
docker version
docker compose version
docker compose build
```

Если вы получили от меня архив готовых образов, вместо сборки загрузите его:

```sh
docker load -i rgbd-images.tar
```

Команда `docker image ls` должна показывать `mirea-rgbd-vo:noetic-v1` и `mirea-rgbd-viewer:0.23.4`.

## 1. Открыть контейнер и собрать пакет

**В терминале компьютера**, из папки практики:

```sh
docker compose run --rm lab bash
```

Теперь этот терминал работает **внутри ROS-контейнера**. Выполните в нём:

```bash
source /opt/ros/noetic/setup.bash
cd /lab/catkin_ws
catkin_make -j2
source devel/setup.bash
cd /lab
rosbag info data/tum_rgbd_12s.bag
```

`catkin_make` подготавливает пакет к запуску. Python-нода не компилируется в машинный код. `source devel/setup.bash` добавляет собранный пакет в окружение **текущего терминала**.

Папка практики подключена в контейнер как `/lab`. Поэтому редактировать файлы можно обычным редактором на компьютере: изменения сразу доступны контейнеру.

## 2. Дописать ноду

Откройте [student_node.py](catkin_ws/src/rgbd_vo_lab/scripts/student_node.py), найдите четыре TODO и выполните задания:

1. Создайте `rospy.Publisher` для топика `/vo/pose` с типом `PoseStamped` и очередью 10. Сохраните его в `self.pub`.
2. Создайте три `message_filters.Subscriber` и сохраните их в `self.rgb_sub`, `self.depth_sub`, `self.info_sub`:
   - `self.rgb_sub`: топик `/camera/rgb/image_raw`, тип `Image`, `queue_size=10`, `buff_size=2**25`;
   - `self.depth_sub`: топик `/camera/depth/image_raw`, тип `Image`, `queue_size=10`, `buff_size=2**25`;
   - `self.info_sub`: топик `/camera/rgb/camera_info`, тип `CameraInfo`, `queue_size=10`.

   Удалите строку `raise NotImplementedError(...)`. Готовый блок `TimeSynchronizer` под ней оставьте без изменений.
3. В callback передайте `color, depth, info` в `self.lab.process_messages(...)` и сохраните результат.
4. Если результат не равен `None`, опубликуйте его через свой publisher.

Сохраните файл в UTF-8. Готовую математическую часть менять не требуется.

### Как связаны сообщения

Подписчики создаёте вы. Здесь используем `message_filters.Subscriber`: это ROS-подписчик, который передаёт сообщения синхронизатору. Три независимых `rospy.Subscriber` сами по себе не соберут согласованную тройку для одного callback.

Следующий блок уже находится в заготовке:

```python
self.sync = message_filters.TimeSynchronizer(
    [self.rgb_sub, self.depth_sub, self.info_sub], queue_size=20
)
self.sync.registerCallback(self.callback)
```

Он вызывает `callback(color, depth, info)`, когда получены три сообщения с одинаковым `header.stamp`. В учебном бэге метки заранее согласованы. Порядок аргументов callback соответствует порядку подписчиков в списке.

`queue_size=10` ограничивает очередь каждого подписчика, а `buff_size=2**25` задаёт приёмный буфер в 32 МиБ для крупных сообщений изображений. Очередь синхронизатора `20` хранит сообщения каждого входа в ожидании совпадающих меток. Это разные очереди; параметры для этой работы оставьте указанными.

| Топик | Тип | Содержание |
| --- | --- | --- |
| `/camera/rgb/image_raw` | `sensor_msgs/Image` | RGB-изображение |
| `/camera/depth/image_raw` | `sensor_msgs/Image` | Глубина, формат `32FC1`, метры |
| `/camera/rgb/camera_info` | `sensor_msgs/CameraInfo` | Параметры камеры |
| `/vo/pose` | `geometry_msgs/PoseStamped` | Поза, которую публикует ваша нода |
| `/vo/path` | `nav_msgs/Path` | Путь, который готовый recorder собирает из опубликованных поз |
| `/ground_truth/pose` | `geometry_msgs/PoseStamped` | Эталон для проверки; алгоритм одометрии его не использует |

`process_messages` возвращает готовое сообщение `PoseStamped` либо `None`, если кадр пропущен по настройке или оценка ненадёжна. **При `None` ничего не публикуйте.** Нельзя подставлять старую позу с новой меткой времени и выдавать её за новое измерение.

### Что делает готовый алгоритм

1. Находит ORB-признаки — различимые детали изображений.
2. Сопоставляет детали между опорным и текущим кадрами.
3. По глубине опорного кадра и параметрам камеры получает 3D-координаты деталей.
4. С помощью PnP и RANSAC оценивает движение и отбрасывает ошибочные соответствия.
5. Преобразует относительное движение в позу камеры относительно начала пути.

Начало координат находится в первой камере: X вправо, Y вниз, Z вперёд. Это оптическая система координат камеры. Масштаб в метрах даёт измеренная глубина.

## 3. Собрать и запустить

После сохранения кода **в прежнем ROS-контейнере** выполните:

```bash
cd /lab/catkin_ws
catkin_make -j2
source devel/setup.bash
cd /lab
python3 run_lab.py data/tum_rgbd_12s.bag --out output/attempt01
```

Скрипт запускает `roscore`, вашу ноду через `rosrun rgbd_vo_lab student_node.py`, запись опубликованных поз и `rosbag play`. Отдельно запускать эти процессы не нужно.

Бэг проигрывается со скоростью 0,25, чтобы дать ноутбуку больше времени на обработку. Физические метки времени сообщений не меняются. Перед первым кадром проигрыватель ждёт подключения подписчиков. Эталон читается отдельно при проверке и не передаётся ноде.

После успешного запуска в `output/attempt01/` появятся:

- `report.json` — метрики и результат проверки публикации;
- `poses.bag` — фактически опубликованные позы и путь;
- `student.log` — лог вашей ноды;
- данные кадров для просмотра в Rerun.

Каждый запуск требует **новой папки результата**. Если попытка завершилась ошибкой, после исправления используйте, например, `output/attempt01_retry`. Старые попытки не перезаписываются.

## 4. Посмотреть результат

Откройте **второй терминал на компьютере**, снова в папке с `compose.yaml`. Это не терминал внутри ROS-контейнера.

```sh
docker compose run --rm --service-ports viewer python viewer/show.py output/attempt01 --serve
```

Дождитесь строки `Saved` и откройте **[Rerun в браузере](http://localhost:9090/?url=rerun%2Bhttp%3A%2F%2Flocalhost%3A9876%2Fproxy)**. Терминал viewer должен оставаться запущенным во время просмотра.

Что показывают панели:

- **Траектории:** оранжевая — оценка, зелёная — эталон. Первая вкладка показывает проекцию на плоскость XZ первой камеры, без оси Y. Отдельная вкладка содержит полный 3D-путь.
- **Карта RGB-D:** разреженное облако точек сцены. Двоение объектов может быть следствием ошибки движения.
- **Соответствия:** зелёные линии поддержали модель, красные отвергнуты. Линия соединяет координаты детали в опорном и текущем кадрах; это не вектор скорости.
- **Глубина:** расстояние вдоль оптической оси в метрах. Ноль означает отсутствие измерения.
- **Отслеживание:** состояние обработки, количество признаков, соответствий и поддержавших модель совпадений.
- **Проверка:** отчёт об оценках и ошибках.

Перемещайте указатель времени по кадрам. Если шкала скрыта, включите панель времени в правом верхнем углу Rerun. Для воспроизведения примерно с исходной частотой выберите **10 FPS** вместо стандартных 30 FPS. Скорость просмотра не меняет вычисленные позы.

Для остановки viewer нажмите **Ctrl+C во втором терминале**. Запись `recording.rrd` останется в папке результата.

## 5. Разобрать результат

Откройте `output/attempt01/report.json`. Сопоставьте значения в отчёте с тем, что видно в Rerun: насколько близки траектории, есть ли расхождения и были ли потери отслеживания.

| Поле отчёта | Смысл |
| --- | --- |
| `processed` | Число обработанных кадров |
| `published` | Число опубликованных поз |
| `lost` | Число обработанных кадров, для которых надёжная поза не получена |
| `tracking_fraction` | Доля успешных оценок среди обработанных кадров: `published / processed` |
| `position_rmse_m` | Среднеквадратическая ошибка положения относительно эталона, в метрах |

**RMSE считается только там, где поза опубликована.** Пропуски не входят в эту ошибку. Поэтому при оценке результата учитывайте и ошибку положения, и долю успешных оценок.

1. Дополненный `student_node.py`.
2. Файл `report.json` успешного запуска.
3. Снимок Rerun с оценённой и эталонной траекториями.
4. Короткие ответы своими словами:

   - Откуда в этой задаче берётся масштаб в метрах?
   - Зачем алгоритму нужна глубина?
   - Почему алгоритм может потерять отслеживание?

Объясните цепочку: **кадры → соответствия → 3D-точки по глубине → PnP → преобразование позы → публикация**.

## Повторный запуск и завершение

Если требуется повторить запуск после исправления кода, выполните `run_lab.py` с новой папкой результата. Останавливать ROS-контейнер между попытками не нужно: скрипт завершает запущенные им ROS-процессы.

После занятия остановите viewer через Ctrl+C, затем выполните `exit` в ROS-контейнере. Благодаря `--rm` завершённые контейнеры удалятся автоматически. Код и результаты в папке практики сохранятся.

## Если что-то не работает

| Проблема | Что проверить |
| --- | --- |
| Docker не отвечает | Запустите Docker Desktop и дождитесь готовности Linux engine |
| `TODO` или `Node exited` | Заполните четыре TODO, удалите `raise NotImplementedError(...)`, прочитайте `output/<попытка>/student.log` |
| Пакет не найден | Выполните `catkin_make` и `source devel/setup.bash` в текущем ROS-контейнере |
| `source` не распознаётся | Команды `source` выполняются внутри Bash-контейнера, не в PowerShell |
| `Not all RGB-D frames received` | Ноутбук мог не успеть обработать поток. Повторите в новой папке: `python3 run_lab.py data/tum_rgbd_12s.bag --rate 0.1 --out output/attempt01_slow`. Уменьшается скорость проигрывания, временные метки данных сохраняются |
| Папка результата уже существует | Укажите новую папку через `--out` |
| Порт viewer занят | Остановите предыдущий viewer через Ctrl+C в его терминале |
| Пустой Rerun | Дождитесь строки `Saved`, обновите страницу, проверьте полный адрес с параметром `url=...` |
| Браузер не создаёт графический контекст | Проверьте графическое ускорение в Chrome/Edge; альтернативно откройте `recording.rrd` в нативном Rerun 0.23.4 |

## Данные и ограничения

Используется фрагмент **TUM RGB-D, freiburg1_xyz**. Данные распространяются по CC BY 4.0; авторы и описание подготовки приведены в [data/README.txt](data/README.txt).

Глубина совмещена с RGB. Для учебного бэга ближайшая depth-пара в пределах 20 мс получает метку RGB для точной синхронизации ROS; исходные метки сохранены в `data/tum_rgbd_12s.json`. Глубина преобразована из исходного PNG в метры.

Это учебная одометрия без оптимизации всей карты и замыкания петли. Эталон используется только при проверке, совмещается по первой принятой позе; подгонки масштаба или всей траектории нет.

- [TUM RGB-D](https://cvg.cit.tum.de/data/datasets/rgbd-dataset)
- [Форматы данных и параметры камеры TUM](https://cvg.cit.tum.de/data/datasets/rgbd-dataset/file_formats)
- [OpenCV: PnP](https://docs.opencv.org/4.2.0/d5/d1f/calib3d_solvePnP.html)
- [Rerun](https://rerun.io/)
